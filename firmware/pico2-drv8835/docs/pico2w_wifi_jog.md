# Pico 2 W スマホWi-Fiジョグ手順

## 対象と制約

`pico2w_gcode_drv8835_wifi.uf2`は、Pico 2 W自身をWi-Fiアクセスポイントにして、スマホのブラウザからDRV8835版XY平面ステッパをジョグするファームです。既存のUSB G-codeと`M980`は残しています。

この機能は操作経路だけを追加します。現在検討中の電源容量、直列抵抗、コイル電流、磁力の問題は改善しません。実機試験では従来どおりVM 3 V、電源制限1.5 A、各相1.5 Ωから開始してください。

## GPIO配置

Wi-Fi版もUSB版DRV8835バックエンドと同じGPIOを使用します。起動処理の最初にGP15からGP22を出力Lowへ設定し、Wi-Fi初期化に失敗しても励磁しません。

| 軸・相 | DRV8835入力 | Pico 2 W GPIO |
|---|---|---:|
| X A相 | AIN1 / AIN2 | GP19 / GP20 |
| X B相 | BIN1 / BIN2 | GP21 / GP22 |
| Y C相 | AIN1 / AIN2 | GP15 / GP16 |
| Y D相 | BIN1 / BIN2 | GP17 / GP18 |
| Zサーボ | PWM信号 | GP12（物理16番） |

Pico 2 W、DRV8835、モーター電源、サーボ電源のGNDを共通にします。VMやサーボ電源をPico 2 Wの3V3端子から供給しないでください。サーボは外部5 Vから給電します。

## 接続

1. VMをOFFにしてPico 2 Wを起動します。
2. USBシリアルの起動ログで`WIFI AP`、SSID、URLを確認します。
3. スマホのWi-Fi設定で`PlanarStepper-XXXX`を選びます。
4. パスワード`planar-stepper`を入力します。
5. インターネット未接続の警告が出ても、このWi-Fi接続を維持します。
6. ブラウザで`http://192.168.4.1/`を開きます。

Pico自身のAP専用です。DNSと主要OSの接続確認URLに応答するため、対応端末では操作画面が自動表示されます。家庭内Wi-Fiへの参加、設定保存、インターネット中継は実装していません。

## 画面操作

| ボタン | G-code方向 |
|---|---|
| 上 | Yマイナス |
| 下 | Yプラス |
| 左 | Xプラス |
| 右 | Xマイナス |
| 中央の停止 | 移動キャンセル後、全出力Low |
| ペン上 | `G0 Z1`相当 |
| ペン下 | `G1 Z0`相当 |

駆動モードは、1相を100%励磁する「確実動作 U1」と、2相をsin/cos PWMする「滑らか動作 U8（実験）」から選択できます。既定は確実動作で、移動量は2.5 mmです。滑らか動作へ切り替えると0.625 mmを選択します。移動量は`0.3125 / 0.625 / 2.5 / 10 mm`から変更でき、Feedは30から1000 mm/min、初期値は300 mm/minです。

HTTP要求は1件だけキューへ入り、メインループで既存の`$J=G91 G21 ...`に変換されます。実行中は十字ボタンを無効にし、重複ジョグを受け付けません。中央停止は通信コールバックからプランナのキャンセルフラグを立て、移動ループが約1 ms周期で検出します。

## 内部API

```text
GET /api/jog.cgi?axis=X&direction=1&distance=0.625&feed=300
GET /api/stop.cgi
GET /api/mode.cgi?activeOnly=1&microsteps=1&captureMs=100
GET /api/pen.cgi?state=up
GET /api/pen.cgi?state=down
GET /api/status.shtml
```

`axis`は`X`または`Y`、`direction`は`-1`または`1`、移動量は画面にある4値だけ、Feedは30から1000の整数だけを受理します。不正入力はHTTP 400、実行中の追加要求は`busy`を返します。
`pen.cgi`は`state=up`または`state=down`だけを受理し、メインループで通常のZ G-codeへ変換します。

状態応答例:

```json
{"ready":true,"busy":false,"armed":true,"outputs":false,"activeOnly":true,"microsteps":1,"captureMs":100,"activeMask":0,"xAngle":0,"yAngle":0,"xPhase":"A+","yPhase":"C+","clients":1,"x":0.0000,"y":0.0000,"z":1.0000,"penPulseUs":1000,"penUp":true,"lastResult":"ok"}
```

`activeOnly=1`は移動する軸だけを励磁し、`activeOnly=0`は常にXY両軸を励磁します。`microsteps`は画面で使用する`1`または`8`、`captureMs`はHi-Z解除時と対象軸切替時の捕捉時間で、0から500msです。設定変更時は安全のため一度全出力をLowへ戻し、論理座標を維持したまま電気角を基準相へ同期します。

## 接続できない場合の判定

USBシリアルを115200 baudで開いたまま、スマホ側でネットワークを一度削除してから再接続します。

- `[WIFI AP: clients=0]`のまま: パスワード認証またはWi-Fi関連付けまで到達していません。
- `[WIFI AP: clients=1]`は出るが`DHCPS: client connected`が出ない: DHCP払い出し段階の問題です。
- `DHCPS: client connected`まで出る: IP取得済みです。ブラウザへ`http://192.168.4.1/`を直接入力します。

ファーム0.6.2以降は、スマホの初回DHCP要求だけでなく、要求IPオプションを省略する再接続・リース更新も受理します。インターネット未接続の警告では「このネットワークを使用」を選びます。IP取得済みなのに携帯回線へ迂回する場合だけ、確認中はモバイルデータ通信を一時的にOFFにします。

## 安全な実機確認

1. VMをOFFにし、起動直後からGP15からGP22がLowであることを確認します。
2. スマホからAPと操作画面を開き、座標と`出力 Hi-Z`が表示されることを確認します。
3. 十字ボタンを連打し、実行中に2件目が入らないことを確認します。
4. VM 3 V、電流制限1.5 A、各相1.5 Ωで、「確実動作 U1」、移動量2.5 mmからYを試します。
5. 次にX、最後にXYを交互に操作します。
6. 10 mmの低速ジョグ中に中央停止を押し、200 ms以内に停止して出力がLowへ戻ることを確認します。
7. 移動中にブラウザを閉じます。指定距離以上に継続せず、移動完了500 ms後に`出力 Hi-Z`になることを確認します。
8. USBから`M122`を送り、座標、armed状態、`single-phase`、`capture_ms=100`、現在相、対象軸、出力状態を照合します。

標準G-codeでの比較には次を使用します。

```gcode
M18
M980 U1 X100 Y100 H500 A1 C100
M17
G91
G1 X2.5 F300
G1 X-2.5 F300
G1 Y2.5 F300
G1 Y-2.5 F300
M18
```

回路の発熱、電源CC移行、異音、抵抗の過熱を検出した場合は、画面操作を続けずVMをOFFにします。
